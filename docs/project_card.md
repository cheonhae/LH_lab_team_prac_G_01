# 프로젝트 카드 — G3조

> 팀 PRD ① 블록 첫 실습 · 조원이 말하고 드라이버 세션이 채워 커밋합니다(`[팀] 프로젝트 카드`). 인터뷰 전에 정하는 것이라 거칠어도 됩니다. PRD가 나오면 1·2절만 다시 맞춥니다.

## 1. 주제

- 출발점: 사전 설문 13번 희망 실습주제
- 한 줄: 주거복지 담당자가 · 공공임대 입주 신청 서류의 누락·발급일을 한 건씩 확인하다 놓치는 불편을 · 필수서류 대조와 발급일 확인 웹앱으로 줄인다
- 넣을 검증 절차: ☑ 근거 대조 ☐ 계산 검산 ☑ 정합 검사 (1개 이상)
  - 근거 대조: 제출 서류를 신청 유형별 필수서류표(가상)와 대조
  - 정합 검사: 발급일과 가상 모집공고일 비교, 시작 페이지 요약 숫자와 기능 페이지 숫자 일치
  - 계산 검산은 보완 기한 계산이 '다음'으로 빠지면서 해제했다

## 2. 범위

결과물: `tools/` 아래 여러 페이지 HTML 웹앱 — 시작 페이지(`index.html`) + 기능 페이지 2개(`pages/`) + 공통 파일(`assets/common.js`·`assets/style.css`), GitHub Pages 배포. 저장은 localStorage 키 하나 + JSON 백업 내보내기·가져오기.

| 오늘 만들 것 (MVP) | 오늘 만들지 않을 것 |
|---|---|
| 기능 A(`pages/docs_check.html`): 신청 서류 CSV(서류 1건 = 1행)를 파일 선택으로 불러와, 신청 유형별 필수서류표(가상)와 대조해 누락 서류 표시 | 보완 기한 계산(가상 휴일 표 반영, 임박·초과 표시) — '다음' |
| 기능 B(`pages/docs_date.html`): 기능 A가 저장한 서류 목록을 읽어, 발급일이 가상 모집공고일 기준 유효 기간을 벗어난 서류 표시 | 붙여넣기 입력, 상세 통계 — '다음' |
| 시작 페이지(`index.html`): 메뉴·요약(누락 n·발급일 어긋남 n)·백업 내보내기·가져오기·비우기 | 로그인·청약·사회보장정보시스템 연동, 소득·자산 계산 |
| 세 페이지 모두 결과는 "점검 대상"으로만 표시하고 "담당 검토 후 확정" 문구를 보인다 | 입주 자격·당첨 판정(담당 검토 후 확정) |
| 수용 기준 예: 표본 신청 20건·서류 70행 → 누락 4·발급일 어긋남 3, 시작 페이지 요약도 같은 숫자 (PRD 5절 S1~S4) | 안내 문자 발송, 인쇄 양식 |

## 3. 역할과 리뷰 짝

| 역할 | 이름 | 리뷰 짝 (이 사람의 PR을 승인) |
|---|---|---|
| ① 통합·화면 | A | B (②) |
| ② 기능 A | B | A (①) |
| ③ 기능 B | A | B (④) |
| ④ 검증·데이터 | B | A (③) |

- 조원: 2명(A, B). 한 사람이 역할 2개를 맡는다 — A: ①·③, B: ②·④
- 역할 배정 이유: 리뷰 짝(①↔②, ③↔④)이 늘 다른 사람이 되도록 나눴다. 자기 PR을 자기가 승인하는 일이 생기지 않는다.
- 서기: B (`docs/team_decisions.md` 기록)
- 표본 데이터 사용 승인: ④ (B)
- PRD 범위 변경: 조원 A·B 합의(서기 B가 `docs/team_decisions.md`에 기록)

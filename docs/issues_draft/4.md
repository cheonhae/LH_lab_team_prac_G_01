## 목적

## 완료 기준

> ④ 이슈는 화면이 아니라 파일·문서 작업입니다. 아래 기준은 해당 파일을 열어 판정합니다. 화면 판정은 이 기준표로 ①②③의 PR에서 합니다.


- ☐ 표본: `data/team_sample.csv` — 가상, UTF-8, 머리행 `신청번호,신청유형,서류명,발급일`, 서류 70행(신청 20건), 신청번호는 `R-001` 형식만(이름·연락처 없음)
- ☐ 표본을 엑셀로 열어 세면 누락 4건·발급일 어긋남 3건이고, 일부러 넣은 함정 행(확인 필요 n건)의 신청번호와 사유가 AC4와 2절 기대 결과에 적혀 있다
- ☐ 기대 결과: `tests/acceptance.md` 2절에 ④가 표본을 직접 보고(엑셀 필터 등 두 번째 방법) 적는다. 웹앱 결과를 옮겨 적지 않는다
- ☐ 수용 기준표: AC1(S1)·AC2(S2)·AC3(S3·S4)·AC4(함정 — 기능 A·B와 시작 페이지 "확인 필요 n")·AC5·AC6의 '하는 것'과 '기대'가 "어느 페이지에서 무엇을 하면 → 어디에 무엇이 보인다" 문장으로 적혀 있다
- ☐ 경계 입력: 4절 B1·B2(예: 빈 행·같은 서류 두 번, 발급일 형식 오류)에 넣을 값과 화면에 보일 숫자·문구가 적혀 있다
- ☐ 파일 검사: `tests/run_acceptance.py`의 `PAGES`를 `tools/index.html`·`tools/pages/docs_check.html`·`tools/pages/docs_date.html`로, `STORAGE_KEY`를 `"teamG3_app"`으로 채운다. 검사 함수는 고치지 않는다

## 검증 방법

- `python tests/run_acceptance.py` 실행 — 실패 0건, 아직 없는 파일은 미실행
- 표본 CSV를 엑셀로 열어 누락 4·발급일 어긋남 3·확인 필요 n을 손으로 다시 센다
- 작업 규칙: 웹앱 결과가 기대와 다르면 기준을 낮추지 않고 해당 이슈에 알린다

## 목적

- 제목 규칙: `[검증]` 표본·수용 기준표·파일 검사 설정
- 요구사항: `docs/team_plan.md` R1~R3 전체 — 성공 시나리오 S1~S4를 배포 주소에서 판정할 기준과 가상 표본을 먼저 고정한다

## 완료 기준

- ☐ 표본: `data/team_sample.csv` — 가상, UTF-8, 머리행 `신청번호,신청유형,서류명,발급일`, 서류 70행(신청 20건), 신청번호는 `R-001` 형식만(이름·연락처 없음)
- ☐ 표본에 누락 4건·발급일 어긋남 3건이 들어 있고, 일부러 넣은 함정 행을 정해 AC4에 적는다
- ☐ 기대 결과: `tests/acceptance.md` 2절에 ④가 표본을 직접 보고(엑셀 필터 등 두 번째 방법) 적는다. 웹앱 결과를 옮겨 적지 않는다
- ☐ 수용 기준표: AC1(S1)·AC2(S2)·AC3(S3·S4)·AC4(함정)·AC5·AC6과 경계 입력 B1·B2를 채운다
- ☐ 파일 검사: `tests/run_acceptance.py`의 `PAGES`를 `tools/index.html`·`tools/pages/docs_check.html`·`tools/pages/docs_date.html`로, `STORAGE_KEY`를 `"teamG3_app"`으로 채운다. 검사 함수는 고치지 않는다
- ☐ 실패할 때: 기대와 다른 결과가 나오면 기준을 낮추지 않고 해당 이슈에 알린다

## 검증 방법

- `python tests/run_acceptance.py` 실행 — 실패 0건, 아직 없는 파일은 미실행
- 표본 CSV를 엑셀로 열어 누락 4·발급일 어긋남 3을 손으로 다시 센다

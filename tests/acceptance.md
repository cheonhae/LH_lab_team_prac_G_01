> 작성: ④ 검증·데이터 담당 · 페이지별 개발 블록 첫머리에 1차 · 커밋 머리 `[팀-검증데이터]`

## 3. 수용 기준

AC1~AC4·AC6은 사람이 화면에서, AC5와 파일 검사 F1~F4는 `python tests/run_acceptance.py`로 확인합니다.

|---|---|---|---|---|---|
| AC1 | S1 | 시작 페이지에서 '비우기'를 누르고 기능 A(누락 서류 대조) 페이지로 이동 → 파일 선택으로 `data/team_sample.csv`를 불러온다 → 기능 A 페이지의 누락 목록을 본다 | 기능 A페이지의 누락 목록에 4건이 보인다 | ☐ 통과 ☐ 수정 | ☐ 통과 ☐ 수정 |
| AC2 | S2 | AC1에 이어 파일을 다시 불러오지 않고 기능 B(발급일 유효 확인) 페이지로 이동 → 기능 B 페이지의 발급일 어긋남 목록을 본다 | 기능 B페이지의 발급일 어긋남 목록에 3건이 보인다 | ☐ 통과 ☐ 수정 | ☐ 통과 ☐ 수정 |
| AC3 | S3 | AC2에 이어 시작 페이지로 이동 → 요약 세 숫자를 보고 '백업 내보내기'를 누른다 → 내려받은 파일을 확인한다 | 내려받은 파일이 보인다 | ☐ 통과 ☐ 수정 | ☐ 통과 ☐ 수정 |

## 4. 경계 입력 (다른 조를 시험할 때 우리가 쓸 것 — 2개, 상급 조는 4개)

| # | 경계 입력 | 예상되는 올바른 동작 |
|---|---|---|
| B1 | 빈 값이 있는 건 — 필수 칸(번호·이름 등 그 조의 핵심 칸) 하나를 비운 행과, 칸이 모두 빈 행을 표본 사이에 하나씩 넣는다 | 칸이 모두 빈 행은 건너뛰고 건수에 넣지 않는다. 필수 칸이 빈 행은 결과 숫자에 넣지 않고, 어느 행의 어느 칸이 비었는지 따로 알려 준다(조용히 0이나 정상으로 처리하지 않는다) |
| B2 | 형식이 섞인 건 — 같은 날짜 칸에 `2026-10-05`, `2026/10/05`, `2026.10.5`, `2026-13-05`(없는 날짜)를 섞어 넣는다 | 그 조가 정한 형식(예: `YYYY-MM-DD`)만 날짜로 계산한다. 형식이 다르거나 없는 날짜는 기한·유효 판정에 넣지 않고 "형식 오류" 같은 사유와 함께 따로 보여 준다. 화면이 깨지거나 멈추지 않는다 |

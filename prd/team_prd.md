# 팀 PRD — G3조 공공임대 입주 신청 서류 점검 도구

> PRD 인터뷰(코어 페이스) 결과 · 서기: B · 프로젝트 카드: `docs/project_card.md` · 결정 기록: `docs/team_decisions.md`
> **[가정]** 표시는 인터뷰에서 정하지 않아 일단 이렇게 두고 진행하는 것입니다. `docs/team_decisions.md`에도 같이 적었습니다.

## 1. 프로젝트 개요

- **해결하려는 문제:** 주거복지 담당자가 공공임대 입주 신청 서류를 눈으로 확인하다 보니 필수서류 누락이나 유효 기간을 벗어난 발급일을 놓친다. 보완을 요청한 뒤에는 보완 기한을 따로 챙기기도 어렵다.
- **배경:** 놓친 건이 뒤늦게 발견되면 신청자에게 다시 연락하거나 처리를 되돌려야 하고, 이것이 감사·민원 지적으로 이어질 수 있어 부담이 된다.
- **기대 변화:**
  - 서류를 한 장씩 넘겨 보던 확인 → 누락·발급일 어긋남 목록이 먼저 뜨고, 담당자는 그 건만 검토한다.
  - 메모로 챙기던 보완 기한 → 화면에서 임박·초과로 바로 보인다. (이번 범위 밖, '다음')

## 2. 사용자 분석

- **주 사용자:** 주거복지지사 창구에서 입주 신청 접수와 서류 확인을 하는 실무자. 모집 기간에는 하루에 수십 건을 본다. 다음 사용자는 이 업무에 새로 배치돼 필수서류 기준이 아직 손에 익지 않은 사람.
- **사용 맥락:** 모집 마감 뒤 신청 서류 목록을 내려받아 한꺼번에 점검한다. 보완 기간 중에는 매일 아침 기한을 확인한다('다음' 기능).
- **현재 해결 방식과 한계:**
  - 신청 목록 엑셀에 서류 칸을 만들어 O/X를 손으로 입력한다. 입력 실수가 생기고, 발급일 비교는 결국 눈으로 한다.
  - 보완 기한은 메모·달력으로 챙긴다. 휴일을 빼고 날짜를 세다가 틀리거나 빠뜨린다.

## 3. 기능 요구사항

### 3-1. 형태

- `tools/` 아래 **여러 페이지 HTML 웹앱**이다.
  - `tools/index.html`: 시작 페이지 — 메뉴, 저장된 데이터 요약, 백업 내보내기·가져오기, 비우기
  - `tools/pages/` 아래 기능 페이지 2개 (3-2)
  - 공통 파일: `tools/assets/common.js`(저장 함수만), `tools/assets/style.css`
- 병합된 main을 **GitHub Pages**로 배포한다. 파일을 더블클릭해 열어도 같게 동작한다.
- 서버·로그인·설치·외부 라이브러리·외부 주소·외부 전송은 없다.

### 3-2. 기능과 페이지

| 페이지 | 파일 | 하는 일 (한 줄) |
|---|---|---|
| 기능 A — 누락 서류 대조 | `tools/pages/docs_check.html` · `tools/assets/docs_check.js` | 신청 서류 CSV를 파일 선택으로 불러와, 신청 유형별 필수서류표(가상)와 대조해 빠진 서류가 있는 신청을 표시한다. |
| 기능 B — 발급일 유효 확인 | `tools/pages/docs_date.html` · `tools/assets/docs_date.js` | 기능 A가 저장한 서류 목록을 읽어, 발급일이 가상 모집공고일 기준 유효 기간을 벗어난 서류를 표시한다. |

- 두 페이지와 시작 페이지 모두 결과를 "점검 대상"으로만 표시하고, 화면에 **"담당 검토 후 확정"** 문구를 보여 준다. 입주 자격·당첨은 판정하지 않는다.
- **[가정] 입력 CSV:** 파일 하나, 서류 1건 = 1행. 열은 `신청번호, 신청유형, 서류명, 발급일`(UTF-8). 표본은 신청 20건·서류 70행이다.
- **[가정] 기준값 위치:** 신청 유형별 필수서류표는 `docs_check.js`에, 가상 모집공고일과 유효 기간 규칙은 `docs_date.js`에 상수로 둔다. 구체 값은 ④가 표본과 함께 정해 `docs/design.md` 2절에 적는다.
- **[가정] 유효 기간 규칙:** 가상 모집공고일 이후에 발급된 서류만 유효로 본다. 공고일 전 발급분은 "발급일 어긋남"으로 표시한다.

### 3-3. 차별점

1. 사람이 기억하던 필수서류표와 유효 기간을 도구가 갖고 있어서, 신규 배치자도 같은 결과를 얻는다.
2. O/X를 손으로 입력하지 않고, 제출 서류 목록을 읽어 빠진 것만 자동으로 찾는다.
3. 날짜 비교를 도구가 해서 눈으로 비교하다 놓치는 일이 없다.

### 3-4. 다음 (이번에 만들지 않음)

- 붙여넣기 입력, 담당자별·유형별 상세 통계
- 로그인, 청약·사회보장정보시스템 연동, 소득·자산 계산, 안내 문자 발송, 인쇄 양식

## 4. 비기능 요구사항

- **사용 환경:** 사무실 PC 브라우저. GitHub Pages 주소와 파일 더블클릭 둘 다 동작한다.
- **페이지 사이 흐름:**
  - 기능 A가 CSV에서 읽은 서류 목록과 누락 점검 결과를 저장한다 → 기능 B가 그 서류 목록을 읽어 발급일을 확인하고 결과를 저장한다.
  - 시작 페이지는 두 결과를 읽어 누락 n · 발급일 어긋남 n · 확인 필요 n을 요약한다. 확인 필요 n은 기능 A·B에서 판정하지 못한 행(빈 값·형식 오류 등)의 합이다.
- **저장:**
  - 브라우저 안 localStorage 키 하나에 JSON으로 저장한다. **[가정] 키 이름:** `teamG3_app` (`docs/design.md` 2절 규칙 `team{조 번호}_app`을 따름)
  - 모든 페이지는 `common.js`의 공통 함수(`loadData`·`saveData`·`exportJson`·`importJson`·`clearData`)로만 저장소를 쓴다.
  - 시작 페이지에서 JSON 백업 파일 **내보내기·가져오기**와 비우기를 할 수 있다.
- **데이터 민감도:**
  - 신청자는 가상 신청번호(`R-001` 등)로만 구분한다. 이름·연락처·주민번호·소득·자산 칸은 두지 않는다.
  - 필수서류표·모집공고일은 모두 가상 값이다.
- **제약:**
  - 만드는 시간은 약 2시간이다.
  - 배포 주소는 누구나 열 수 있다. 실명·연락처·실제 자료를 화면·표본·코드 어디에도 넣지 않는다.
  - 판단은 확정하지 않고 화면에 "담당 검토 후 확정"으로 보인다.
  - 인원은 2명이 역할 4개를 맡는다(A: ①·③, B: ②·④).

## 5. 성공 지표

- **성공 모습:** 오늘 시연에서 배포 주소로 가상 표본을 불러왔을 때, 점검 숫자가 손으로 센 값과 같고, 세 페이지가 데이터를 이어서 읽어 요약까지 보인다.

### 성공 시나리오 (페이지를 오가며 화면에서 판정)

- **S1.** 기능 A 페이지에서 표본 CSV(신청 20건·서류 70행)를 파일 선택으로 불러오면 → 기능 A 페이지에 누락 4건이 신청번호(`R-…`)·신청 유형·빠진 서류 이름과 함께 보이고, 이름·연락처 칸은 없으며, "담당 검토 후 확정" 문구가 보인다.
- **S2.** 파일을 다시 불러오지 않고 기능 B 페이지로 이동하면 → 기능 B 페이지에 발급일 어긋남 3건이 발급일·가상 모집공고일과 함께 보이고, "담당 검토 후 확정" 문구가 보인다.
- **S3.** 시작 페이지로 이동해 백업 내보내기를 누르면 → 시작 페이지 요약에 누락 4 · 발급일 어긋남 3 · 확인 필요 n(④가 표본에 넣은 함정 수)과 "담당 검토 후 확정" 문구가 보이고, JSON 백업 파일이 내려받아진다.
- **S4.** 시작 페이지에서 비우기를 누른 뒤 S3의 백업 파일을 가져오면 → 비우기 직후 요약이 0으로 바뀌고, 가져온 뒤에는 시작 페이지 요약과 기능 A·B 페이지에 다시 누락 4 · 발급일 어긋남 3이 보인다.

### 참고 지표 (표본으로 판정하지 않음)

- 신규 배치자가 설명 없이 CSV를 불러와 점검 대상을 찾는가
- 서류 점검에 드는 시간이 엑셀 O/X 방식보다 줄었는가
- 놓친 건을 되돌리는 일과 감사·민원 지적이 줄었는가
